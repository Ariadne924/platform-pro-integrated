项目定位

CryptoPaperLab 是一个完全本地运行的加密货币量化模拟盘系统，核心目标是让用户在无需 API Key、无需真实资金的情况下，完整跑通从因子研究 → 信号生成 → 模拟交易 → 盈亏验证的全流程。

核心原则：不接真实交易所，不碰真实资金，所有交易数据均为本地模拟。

核心特性

行情数据

  • 通过 CCXT 直连 Binance 公共只读接口，无需任何 Key
  • 支持现货 + USDT 本位永续（BTC、ETH、SOL、BNB、DOGE 等）
  • 每 10 秒一个 tick，架构支持未来升级 WebSocket
  • 自动回填最近 7 年 1m K 线，CSV 导入与断点续跑

因子系统

  • Markdown 协议文档 + Python 实现 双文件制，MD 是唯一事实来源
  • 12 条严格校验规则，不合规文件显示规则编号 + 字段名
  • 热插拔：丢合规文件进目录，10 秒内自动注册生效
  • 内置 482 个因子（动量、反转、波动率、成交量、微观结构、资金费率/基差等，含 Alpha101 / Alpha360 移植；83 个 active 已通过实算审核）
  • 因子评级：逐因子评测 IC / RankIC / 信号回测指标并给出 S~D 综合评级，评级榜支持全库横向对比与指标排序

策略工厂

  • 支持双文件制策略（MD + Python）和单文件纯 Python 策略
  • 自然语言需求 → 自动生成合规 Python 策略代码
  • 支持 OpenAI 兼容 API 与 Anthropic API
  • 生成后可一键校验、保存并热注册，即刻在模拟盘上自动下单

模拟交易引擎

  • USDT 本位单账户，现货 + 永续（1～20x 杠杆）
  • 市价单 / 限价单撮合，资金费结算，强平机制
  • 完整风控：单标的名义仓位上限、单笔订单上限、维持保证金率
  • 每笔订单标记 source=manual 或 source=auto，净值曲线持久化

可视化仪表盘

  • 单页 Web 仪表盘（原生 JS + ECharts，无构建工具）
  • 实时 K 线蜡烛图、因子时序图、净值曲线、持仓 / 订单 / 账户统计
  • 因子与策略热插拔状态实时展示，10 秒自动轮询

上传文件规范

在主界面【因子】和【策略】选项卡右侧的「上传文件」区，可拖入或选取文件直接注册。三种文件类型的规范化要求如下，不符合规范的文件会被拒绝并报告具体原因。

① 因子文档（.md）

对应目录 factors/，模板见 factors/TEMPLATE.md。

  • 文件命名：<FACTOR-ID>_<name>.md，如 MOM-001_momentum_20d.md
  • factor_id 格式：^[A-Z]{2,8}-\d{3}$，全库唯一
  • name：snake_case，与实现文件 factors/impl/<name>.py 对应

frontmatter 必填字段：

factor_id
因子唯一标识，如 MOM-001
name
snake_case 因子名
category
分类：momentum / reversal / volatility / volume / technical / microstructure / basis_funding / onchain / sentiment / cross_asset / ml_feature / other
version
语义化版本号，如 1.0.0
status
draft（注册不计算）/ active（参与计算）/ deprecated（仅展示）
frequency
计算频率：tick / 1m / 5m / 1h / 4h / 1d
lookback_bars
回看窗口（正整数，基于 1m 主K线）
inputs
输入字段子集，如 [close, volume]
params
参数字典，原样传给 compute(data, params)
implementation
实现文件路径，如 factors/impl/momentum_20d.py
entry
入口函数名（缺省 compute）
output
含 type / description / direction（值大看多 / 看空）

正文固定 10 个章节（标题齐全且顺序正确）：

  1. 因子概述
  2. 数学定义（至少 1 个 $$...$$ 公式块）
  3. 输入与参数
  4. 计算步骤
  5. 输出与解释
  6. 数据依赖与频率
  7. 边界条件与异常处理
  8. 适用范围与已知局限
  9. 有效性检验记录
  10. 变更日志

② 策略 MD 文档（.md）

对应目录 strategies/，模板见 strategies/TEMPLATE.md。需同时存在实现文件 strategies/impl/<name>.py。

  • 文件命名：<STRATEGY-ID>_<name>.md，如 STR-001_mom_breakout.md
  • strategy_id 格式：^[A-Z]{2,8}-\d{3}$，全库唯一

frontmatter 必填字段：

strategy_id
策略唯一标识，如 STR-001
name
snake_case 策略名
version
语义化版本号
status
draft / active / deprecated
symbols
交易标的列表，["*"] 表示全部
params
参数字典，可选 lookback_bars 控制K线窗口（缺省 200）
max_leverage
策略级杠杆上限，1~20
risk_limits
策略级风控覆盖（可空），与全局取更严
implementation
实现文件路径，strategies/impl/<name>.py
entry
入口函数名（缺省 generate）

正文固定 7 个章节（标题齐全且顺序正确）：

  1. 策略概述
  2. 逻辑与信号定义（至少 1 个 $$...$$ 公式块）
  3. 参数说明
  4. 执行规则
  5. 风控约束
  6. 回测与有效性记录
  7. 变更日志

③ 纯 Python 策略（.py）

对应目录 py_strategies/，完整接口规范见 py_strategies/INTERFACE.md。单文件制，无需额外 MD。

  • 文件命名：<name>.py（建议与 STRATEGY_META.name 一致）
  • strategy_id：以 PYS- 开头（如 PYS-101），与双文件制 STR- 区分

必备模块级常量 / 函数：

STRATEGY_META
dict，必填键：strategy_id / name / version / status / symbols / params / max_leverage
STRATEGY_DESCRIPTION
str（Markdown），含策略概述、数学定义（至少 1 个 $$...$$）、参数表、风控说明
generate(ctx)
主入口函数，每个 tick 调用，返回 list[TargetOrder]；纯函数，禁止网络 IO / 随机性 / 读写全局状态

可选钩子函数： on_init(ctx)（注册后调用一次）、validate_params(params)（注册时静态校验）、on_tick_end(ctx, result)（generate 执行完毕后）。

可用库白名单： numpy / pandas / math / statistics / typing / __future__；禁止 os / sys / requests / ccxt / duckdb / socket / subprocess / pathlib，禁止 open(。

generate(ctx) 接收的 ctx 字段：

data
{symbol: {"kline": df, "funding": df, "oi": df}}，kline 列含 open/high/low/close/volume 等，index 为 UTC
factors
{factor_id: {symbol: 最新值}}
positions
当前持仓列表，含 symbol / side / qty / entry_price 等
equity
当前账户净值（USDT）
params
STRATEGY_META["params"] 原样注入
now
本 tick 时间（UTC Timestamp）

TargetOrder 结构（generate 返回值元素）： symbol（必填）、side（必填，long/short/close）、qty（正数，close 时可省略）、leverage（1~max_leverage，缺省 1）。

提示：上传后文件会触发热重载，注册结果实时反映在左侧列表。文件大小限制 1MB，非法路径会被拒绝。

快速启动

# 进入项目目录
cd cryptopaperlab

# 安装依赖
pip install -r requirements.txt

# 启动（首次启动自动后台回填 7 年历史数据）
python run.py

# 浏览器打开
http://localhost:8000

中国大陆用户需在 config.yaml 中配置 proxy: http://127.0.0.1:7890，否则无法访问 Binance API。

核心约束

  • 仅使用 Binance 公共只读接口，代码中不存在任何 API Key / Secret
  • 所有时间戳以 UTC 存储
  • 所有交易为本地虚拟数据，不与真实交易所交互
  • 因子 / 策略实现必须是纯函数，禁止网络 IO、禁止随机性
