# 机器学习研究框架

## 定位

本模块把 Gold 层历史行情和已有因子接入一条可复现的机器学习研究链路：

`Gold 因子面板 → 时间滚动训练 → 因子权重/预测分数 → 自动回测 → 风险评分 → Web 展示`

当前版本用于研究、比较和筛选策略，不直接连接实盘下单。模型输出必须经过样本外回测和风险门禁；高收益不能抵消不可接受的下侧风险。

## 已实现能力

- 数据：复用平台 Gold 层因子面板和统一 UTC 时间语义，不另建一套数据源。支持把多个 Gold 频率因果对齐到一个决策频率；标签和成交价格始终来自决策频率，低频时间点只向后匹配，禁止读取未来值。
- 验证：按时间使用 Expanding Walk-Forward；训练窗口与测试窗口之间支持 Purge 和 Embargo，避免未来标签泄漏。
- 模型：内置 Ridge、Elastic Net 和确定性的 Tree Stumps 基线；安装 `ml` 可选依赖后可直接运行 LightGBM、XGBoost。统一模型适配器允许后续接入 GPU 或更重模型。
- 研究模式：`single_asset` 对一个标的做择时（默认做多/空仓，可显式允许做空）；`cross_section` 对多个标的截面打分并持有 Top-N。
- 因子推荐：用户指定一个核心因子和候选因子池。核心因子单独回测；模型只使用训练折汇总协同因子的入选频率、方向一致性和权重，最终推荐权重按绝对值归一化为 100%。
- 策略：模型预测转换为截面 Top-N 多头仓位，复用现有统一回测器，并计入手续费和滑点。多标的模式支持等权、逆波动率、风险平价和 HRP 四种资产配置方法。
- 基准：所有模型均与同一批因子的等权标准化组合比较。
- 策略比较：Ridge、Elastic Net、Tree Stumps、集成模型、等权基准和用户选择的已有注册策略，在完全相同的样本外窗口与成本假设下分别回测；先按风险门禁筛选，再按综合分排名。
- 已有策略评分：平台只读取已有策略的仓位信号，不修改其实现；再用本次 Gold 价格和成本重新回测。仓位信号相对未来收益计算 Signal IC/Rank IC，因此沿用同一套 100 分口径。
- 信号阈值研究：可对机器学习连续预测和所选已有策略信号扫描开仓/平仓二维阈值。每个参数点均按相同手续费、滑点和价格重新回测，输出收益、换手率、最大回撤、胜率、滚动窗口和牛/熊/震荡表现；只有相邻参数组成连续区域且同时通过滚动、行情和回撤门禁时才标记为稳定区。只有 0/1 等少量离散值的策略会明确返回“信号分辨率不足”，不会伪造曲面。
- 不确定性：使用成对移动区块 Bootstrap 给出候选策略相对等权的收益差区间与胜出概率，并给出收益/Sharpe/回撤/ES 的 Pareto 前沿，避免只凭单一收益率选模型。
- 市场状态：因果规则识别牛市、熊市和震荡市，并分别展示各状态的样本外表现。
- 风险：历史 VaR 只作为可审计对照；默认风控采用波动率过滤历史模拟（FHS）估计动态 VaR/ES，以 EVT/POT 修正极端损失尾部，并用 HAR-RV 预测短期实现波动率。组合构建取可用估计中更保守的结果主动降低风险资产总仓位，剩余资金记为现金；尾部样本不足时会明确降级，不伪造 EVT 数值。
- 硬风控：组合回撤进入预警/减仓/清仓区间时逐级降低风险；达到硬线或单周期极端损失线后转为现金，经过冷静期再按 25%/50%/75%/100% 分阶段恢复。强平事件不会抹掉，评分仍按风险失败处理。风险指标超限、预警、降仓、清仓、冷静期、恢复和解除只在状态变化时写入审计事件，避免逐根 K 线重复记录。
- 可复现性：完成的任务会持久化请求、结果、时间和签名；相同输入与结果不会重复写入。
- 前端：`/ml.html` 提供任务配置、进度、取消、净值对比、评分拆解、风险和特征权重展示；`/risk-log.html` 独立读取已保存实验，提供风险事件筛选、汇总和明细审计。

## 评分口径

总分 100 分，稳健优先：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 下侧风险与回撤 | 45 | 最大回撤、VaR、ES 等；触发硬门禁时直接判不通过 |
| 跨折与跨行情稳健性 | 20 | 样本外各时间折和牛/熊/震荡状态的一致性 |
| 成本后超额与 Sharpe | 20 | 相对等权基准的净超额及风险调整收益 |
| IC 与 RankIC | 10 | 预测分数与未来收益的截面相关性 |
| 右尾捕获加分 | 最多 5 | 只奖励稳定抓住上涨行情，不能冲抵任何风险门禁 |

默认硬门禁包括：样本外成本后收益为负、最大回撤超限、VaR 超限或 ES 超限。门禁结果和数值阈值会随研究结果一起返回。

## 市场状态识别

第一版使用只依赖当时及以前信息的规则模型：快慢均线趋势、回撤和波动率共同判断 `bull`、`bear`、`sideways`。状态需要连续确认后才切换，降低短期噪声造成的反复跳变。

当前市场状态用于分层评估和稳健性评分，不会自动切换模型或仓位。后续若要做状态条件策略，应作为独立实验验证，防止增加过拟合。

前端默认自动识别，参数收在“高级设置”中；牛熊震荡不是用户手工标注的训练标签，也不是策略主配置。

## 模型、集成与基准

- `ridge`：带 L2 正则的线性模型，让全部有效因子以较稳定的连续权重参与。
- `elastic_net`：同时使用 L1/L2 正则，会把部分弱因子压到零，更适合辅助因子筛选。
- `tree_stumps`：多个浅层阈值规则的加法模型，用于捕捉简单非线性门槛。
- `lightgbm`：原生 LightGBM 回归器，适合大量表格因子和非线性关系；未安装依赖时能力接口会明确标为不可用。
- `xgboost`：原生 XGBoost 回归器，是另一条强树模型基线；未安装依赖时不会伪装成可训练模型。
- `ensemble`：所有本次成功训练模型预测的等权平均，是派生的集成方案，不是额外训练模型。
- `equal_weight`：候选因子等权组合，是非机器学习基准。
- `core_factor`：只使用核心因子，是非机器学习的单因子基准。
- `existing_strategy`：平台中已注册策略的原始仓位信号，经当前研究任务的数据、窗口和成本统一重测后的候选。

排行榜比较的是最终可交易方案，因此行数会多于训练模型数；真正训练的内置模型仍然只有三个。

任务状态为 `queued`、`running`、`done`、`error` 或 `cancelled`。完成结果包含模型指标、等权基准、已有策略评分、净值曲线、市场状态表现、历史/FHS/EVT 风险估计、HAR-RV 波动率预测、主动风险缩放、资产权重、综合评分、门禁和推荐因子权重。单个已有策略无法生成信号或与样本外窗口不重合时，会写入 `existing_strategy_errors`，不会掩盖其他候选的结果。

默认 `hybrid_fhs_evt` 的选值规则是：VaR 和 ES 分别取历史模拟、FHS 和有效 EVT/POT 估计的最大值；年化波动率取样本波动和 HAR-RV 预测的最大值。`filtered_historical` 只启用 FHS/HAR-RV，`historical` 仅用于基线复现。上述估计负责事前缩仓，回撤/单周期损失熔断仍是独立的最后防线。

## 开平仓阈值稳定区

阈值研究默认关闭，因为每增加一个策略都会对全部开仓/平仓组合重新运行历史回测。启用后流程为：

1. 将可用连续信号的前 25%（且不少于 20 个周期）作为独立校准段，只用校准段信号分布生成实际阈值；后续评价段不参与阈值生成，避免偷看未来信号分布。
2. 使用状态机执行开仓和平仓，避免把每一期独立分类误当作有持仓记忆的策略。
3. 每个阈值点复用统一回测器，计入手续费和滑点，计算收益、换手率、回撤和胜率。
4. 在滚动时间窗口以及牛市、熊市、震荡市中分别计算表现。
5. 检查相邻阈值点的正收益比例和收益离散度，再将通过门禁的相邻点连接成稳定区。

推荐阈值只会从连续稳定区中选择。若没有稳定区，前端会明确显示没有通过，而不是返回整张曲面中的最高收益点。诊断分仅用于稳定区内部排序，不属于策略主评分，也不能替代严格样本外验证。

安装增强模型：

```bash
pip install -e ".[ml]"
```

服务启动后应先读取 `/api/v1/ml/capabilities`；前端也以该接口为准启用或禁用可选模型，避免环境未安装依赖却提交不可执行任务。

`/api/v1/ml/coverage` 只读检查所选币种、频率和因子依赖在本地 DuckDB 中对研究窗口的覆盖率，不会触发下载。前端提交前自动预检；覆盖不足时由用户决定是否继续让数据提供器尝试远端补取。

## 策略比较协议

比较协议版本为 `shared-window-risk-first-v1`：

1. 所有候选只使用彼此共同存在的样本外时间点。
2. 使用相同的 Top-N 组合规则、手续费、滑点和再平衡频率。
3. 风险门禁失败的候选排在所有合格候选之后，高收益不能覆盖门禁。
4. 合格候选再按风险优先综合分、回撤和总收益依次排序。
5. 相关系数不可定义时返回 `null`，不把 `NaN` 写入 API。
6. Bootstrap 区间只是研究不确定性描述，不作为显著性或实盘收益保证。
7. 已有策略使用其仓位作为预测分数计算 Signal IC/Rank IC；信号会按标的向前持有到下一次调仓，首个信号之前保持空仓。

第二轮设计参考了以下开源项目的公开工程思路，未复制其策略实现：

- [Microsoft Qlib](https://github.com/microsoft/qlib)：将预测模型与组合策略解耦，同时比较 IC 和组合回测表现。
- [Freqtrade](https://github.com/freqtrade/freqtrade)：多策略使用同一份数据和同一时间频率批量回测并输出统一摘要。
- [skfolio](https://github.com/skfolio/skfolio)：Walk-Forward、Purge/Embargo、多个样本外路径及风险度量。
- [vectorbt](https://github.com/polakowo/vectorbt) / [pyfolio](https://github.com/quantopian/pyfolio)：基准收益、交易成本、回撤和 Bootstrap 风险统计。

## 工程边界与后续扩展

- 当前后台任务状态保存在 Web 进程内存中，适合单机研究演示；服务重启后任务进度丢失，取消也只能在阶段边界生效。已完成实验结果持久化，不随任务队列一起丢失。
- 当前模型以 CPU 训练为默认路径，没有声称完成大规模训练、超参数搜索或 GPU 加速。
- 数据准备、时间切分、模型预测、信号转换、回测和评分已经拆开。后续模型适配器必须遵循相同的训练折拟合/测试折预测边界。
- 后续可把任务注册表替换为 Redis/Celery、RQ 或独立训练服务，并接入 PyTorch 时序模型和 GPU worker；这些目前是扩展方向，不是已交付能力。
- 多频率对齐能力已经交付，但仓库本地缓存是否有对应的 1h/4h Gold 数据仍取决于回填任务；框架可运行不等于真实历史数据已自动补齐。
- 多频率与多源研究的已知算法边界和论文检索词见 [`算法问题与论文检索方向.md`](算法问题与论文检索方向.md)。
- 高维高频场景应优先使用训练折内特征筛选、相关性去冗余、稀疏正则、分块读取和并行搜索；所有预处理必须只在训练折拟合。
- 市场状态规则、评分权重和风险阈值均应版本化。任何变更都必须重新跑样本外验证，不沿用旧评分。
